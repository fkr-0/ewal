=ewal= is a pywal-compatible, terminal-aware color and theme toolkit for Emacs.
It can read =~/.cache/wal/colors.json= or use one of the bundled palettes, and
provides adaptors for Doom themes, Spacemacs themes, Evil cursors, and
mode-lines.

The core package uses only Emacs libraries.  Doom, Spacemacs, Evil, and
Transient are dependencies of their respective optional integrations rather
than of palette loading itself.

* Highlights

- More than 200 bundled dark and light palettes.
- Display-independent hexadecimal color parsing suitable for batch Emacs and CI.
- WCAG relative-luminance and contrast calculations.
- Contrast-safe semantic roles for =foreground=, =cursor=, =comment=, and
  =highlight=.
- Doom and Spacemacs adaptors that repair low-contrast colors before themes are
  constructed.
- Evil cursor and mode-line colors that remain distinct from the editor
  background.
- Batch-friendly palette auditing and optional Transient interfaces.

* Usage

** Read colors

#+begin_src emacs-lisp
(require 'ewal)

;; Load pywal's JSON when it exists, otherwise use the configured bundled
;; palette.  Calling this explicitly is optional; `ewal-get-color' loads lazily.
(ewal-load-colors)

;; Positive shades lighten; negative shades darken.
(ewal-get-color 'magenta 4)
(ewal-get-color 'background -2)
#+end_src

** Use bundled palettes

#+begin_src emacs-lisp
(setq ewal-use-built-in-always t
      ewal-dark-palette-p t
      ewal-built-in-palette "sexy-material")

;; Reload after changing palette settings.
(ewal-load-colors nil t)
#+end_src

The default bundled-palette path is resolved relative to the installed =ewal=
library.  It no longer assumes =~/.emacs.d/ewal/palettes/=.  To use a custom
palette tree:

#+begin_src emacs-lisp
(setq ewal-built-in-palette-path "~/path/to/palettes/")
#+end_src

To use a nonstandard pywal-compatible JSON file:

#+begin_src emacs-lisp
(setq ewal-json-file "~/path/to/colors.json")
(ewal-load-colors nil t)
#+end_src

** Contrast policy

The palette loader derives missing semantic roles and guarantees that they are
not equal to the base background.  The defaults are:

- ordinary text: =4.5:1=
- cursors, comments, highlights, and UI boundaries: =3.0:1=

These thresholds can be customized through
=ewal-color-minimum-text-contrast= and =ewal-color-minimum-ui-contrast=.

Contrast is calculated using the WCAG sRGB linearization formula.  Hexadecimal
colors are parsed directly, so batch Emacs does not depend on the active
terminal's color table.

** Doom themes

#+begin_src emacs-lisp
(require 'ewal-doom-themes)
(require 'ewal-generate-doom-theme)

(setq ewal-doom-themes-min-contrast 4.5
      ewal-doom-themes-min-ui-contrast 3.0
      ewal-doom-themes-preview-limit 8)

;; Generate a theme from a palette JSON file.
(ewal-generate-doom-theme-interactive)

;; Audit the active Doom theme.
(ewal-doom-themes-check-contrast)
#+end_src

The Doom adaptor enforces contrast while resolving semantic colors, and the
generator normalizes supplied palettes before producing face definitions.  A
palette that assigns the same color to foreground and background is repaired
rather than emitted unchanged.

** Spacemacs themes

#+begin_src emacs-lisp
(require 'ewal-spacemacs-themes)

(setq ewal-spacemacs-themes-min-contrast 4.5
      ewal-spacemacs-themes-min-ui-contrast 3.0)

(load-theme 'ewal-spacemacs-modern t)
#+end_src

The Spacemacs adaptor checks text and UI roles separately.  Background roles
are not incorrectly audited against themselves.

** Evil cursors and mode-lines

#+begin_src emacs-lisp
(require 'ewal-evil-cursors)

(setq ewal-evil-cursors-obey-evil-p t)
(ewal-evil-cursors-get-colors :apply t)

;; Include Spacemacs cursor integration when available.
(ewal-evil-cursors-get-colors :apply t :spacemacs t)
#+end_src

Cursor backgrounds are checked against the editor background, and text-bearing
mode-line faces receive a foreground that meets the text contrast threshold.

** Audit palettes

Interactive report:

#+begin_src emacs-lisp
(require 'ewal-palette-utils)
(ewal-audit-palettes-contrast "~/path/to/palettes" 4.5)
#+end_src

Pure batch report:

#+begin_src sh
emacs --batch -Q -L /path/to/ewal \
  --eval "(progn (require 'ewal-palette-utils) \
          (ewal-audit-palettes-contrast-batch \"/path/to/palettes\" 4.5))"
#+end_src

Optional Transient front ends are loaded only when requested:

#+begin_src emacs-lisp
(ewal-palettes-transient)
(ewal-check-contrast-panel)
#+end_src

* Development with Eldev

The repository includes an =Eldev= project configuration.  It installs Doom,
Spacemacs, Transient, and lint dependencies into an isolated development
environment and keeps them separate from the user's Doom package tree.

#+begin_src sh
eldev test
eldev compile --warnings-as-errors
eldev lint
#+end_src

The test suite covers WCAG reference values, headless hexadecimal parsing,
semantic role repair, Doom and Spacemacs adaptor thresholds, Evil cursor
contrast, and every bundled JSON palette.

This repository contains several MELPA package boundaries in one tree.  A
single repository-wide =package-lint= invocation therefore misidentifies
subpackage headers and dependencies relative to =ewal.el=.  The default Eldev
lint command runs Checkdoc and Relint; run =package-lint= separately for each
release package or from a CI matrix whose main file is the corresponding
package entrypoint.

Declarative Doom and Spacemacs theme entrypoints use =no-byte-compile: t=, as
theme macros produce source forms that are not useful or reliable as ordinary
byte-compiled libraries.  Reusable helper and adaptor libraries are compiled
with warnings treated as errors.
